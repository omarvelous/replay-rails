# Standard: Database Migrations

## timestamps-first Convention

Always place `t.timestamps` as the **first** column declaration inside every `create_table` block.

```ruby
# Correct
create_table :accounts do |t|
  t.timestamps
  t.string :name, null: false
  t.string :phone
end

# Incorrect
create_table :accounts do |t|
  t.string :name, null: false
  t.string :phone
  t.timestamps
end
```

## Why

`created_at` and `updated_at` are static infrastructure columns — they are present on every table and almost never change. Placing them first:

- Keeps them visually adjacent to the implicit `id` primary key
- Ensures every migration's "scaffolding" columns appear in a consistent location
- Lets business columns appear in the order they were added over time, making schema evolution easier to read at a glance

## Applies To

All `create_table` calls in migration files, including those generated by `rails generate model` or `rails generate migration`. After generating, inspect and reorder if needed before running `db:migrate`.

## Does Not Apply To

`add_column` migration calls — these don't have a `create_table` block, so there's nothing to reorder.

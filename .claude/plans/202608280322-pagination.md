# Plan: Pagination

## Current state

Five index pages already paginate. Show pages render unbounded
collections inline.

### QR Code scans — nested resource

QR Code show currently loads scans with `.limit(50)`. Scans are
the one show-page collection that makes sense as a nested resource:

- Direct FK — `QrScan belongs_to :qr_code`
- Genuinely unbounded — a popular QR code could have thousands
- Users want to browse history — "when was it scanned? by whom?"
- Natural URL — `/qr_codes/:id/scans`

**Approach:** Show page displays last 5 scans with a "View all scans"
link. The link goes to a nested `QrScansController` index with
full pagination.

```ruby
# Route
resources :qr_codes, only: %i[ index show ] do
  resources :scans, controller: "qr_scans", only: :index
end
```

```ruby
# Controller
module App
  class QrScansController < App::BaseController
    def index
      @qr_code = Current.account.qr_codes.find(params[:qr_code_id])
      authorize! @qr_code, to: :show?
      @pagy, @scans = pagy(@qr_code.scans.order(created_at: :desc))
    end
  end
end
```

### Show page collections — leave as-is

Everything else on show pages is inherently bounded or better
served by filters (a future plan):

- **Listing agents** — 3-4 per listing. Tiny.
- **Listing ads** — 5-10 per listing. Bounded by content creation.
- **Agent listings** — could filter on listings index later.
- **Site screens** — `ScreensController` already supports `site_id` param.
- **Playlist ads** — this IS the content. Showing all is the point.
- **Screen content loop** — mirrors the playlist.
- **Ad playlists** — could filter on playlists index later.
- **Lead assignment history** — 2-3 reassignments at most.

These are candidates for a future "filters on index pages" plan,
not pagination.

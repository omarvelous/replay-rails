# Plan: Audit Trail

## Why

Multi-user accounts need accountability. "Who deleted that listing?"
"When was this lead reassigned?" "Who changed the playlist?"
Without an audit trail, there's no way to answer these questions.

Also needed for:
- **Compliance** — brokerages may need records of data changes
- **Debugging** — understanding state changes when something looks wrong
- **Trust** — agents see that their actions are recorded, reducing careless changes

---

## Gem vs hand-rolled

### paper_trail

- Mature, widely used, Rails community standard
- Automatic versioning — tracks every change to tracked models
- Stores full object snapshots (before/after) as YAML/JSON
- `who_did_it` via `whodunnit` — integrates with Current.user
- Revert/undo built in
- Can get heavy — stores full serialized objects per change

### Custom ActivityLog model

- Lightweight — stores only what we decide to track
- Human-readable events: "Jane deleted listing 350 Fifth Ave"
- No object serialization bloat
- No undo/revert (would need to build separately)
- More code to maintain — callbacks or service objects for each event

### Recommendation: paper_trail

The auto-tracking is the killer feature. Hand-rolling means adding
callbacks to every model and maintaining event formatting. paper_trail
does this automatically and the `versions` table is queryable.

For display, we render paper_trail versions into human-readable
events — the storage is automatic, the display is custom.

## Which models to track

### Track (user-facing resources that change)

| Model | Why | Ignore |
|-------|-----|--------|
| Listing | Price changes, status changes, address edits | `updated_at` |
| Ad | Headline, layout, theme changes | `updated_at` |
| Playlist | Name, status (draft → published) | `updated_at` |
| Lead | Status changes (new → contacted → qualified → closed) | `updated_at` |
| Agent | Profile edits (name, email, phone) | `updated_at` |
| Site | Name, address changes | `updated_at` |
| Screen | Name, orientation changes | `updated_at` |
| Player | Device creation, registration | `last_heartbeat_at`, `ip_address`, `user_agent`, `updated_at` |
| User | Profile edits | `updated_at` |
| AccountUser | Role assignments and removals | — |
| Invite | Creation, acceptance, revocation | `updated_at` |
| PlaylistAd | "Who added/removed this ad from the playlist?" | — |
| ScreenPlaylist | "Who assigned this playlist to this screen?" | — |
| ScreenPlayer | "Who paired/unpaired this player?" | — |
| LeadAgent | "Who assigned/reassigned this lead?" | — |
| ListingAgent | "Who added/removed this agent from the listing?" | — |

### Don't track (high-volume or machine-generated)

| Model | Why not |
|-------|---------|
| Impression | Machine-generated, thousands per day. Own table is the audit. |
| QrScan | Machine-generated events. Own table is the audit. |
| MetricSnapshot | Computed rollups, not user actions. |
| Session | Login tracking, not content changes. |
| QrCode | Generated automatically, rarely edited. |
| Ads::CollectionAdAd | Managed through CollectionAd, low value standalone. |

## Setup

### Gem

```ruby
gem "paper_trail"
```

### Migration

```bash
rails generate paper_trail:install
rails db:migrate
```

This creates a `versions` table:

```ruby
create_table :versions do |t|
  t.string   :item_type, null: false
  t.bigint   :item_id,   null: false
  t.string   :event,     null: false  # create, update, destroy
  t.string   :whodunnit              # user ID
  t.jsonb    :object                 # serialized previous state
  t.jsonb    :object_changes        # serialized diff
  t.datetime :created_at
end
add_index :versions, [ :item_type, :item_id ]
```

Use `jsonb` instead of the default `text` for object/object_changes —
queryable and more efficient in PostgreSQL.

### Configuration

```ruby
# config/initializers/paper_trail.rb
PaperTrail.config.track_associations = false  # associations tracked via parent
```

### Whodunnit (who made the change)

```ruby
# app/controllers/app/base_controller.rb
before_action :set_paper_trail_whodunnit

private

def user_for_paper_trail
  Current.user&.id
end
```

This sets `whodunnit` on every version to the current user's ID.

### Model integration

```ruby
# app/models/listing.rb
class Listing < ApplicationRecord
  has_paper_trail
  # ...
end
```

One line per model. paper_trail handles the rest — creates a
version record on every create, update, and destroy.

## What gets stored

For each change, paper_trail stores:

```ruby
version = listing.versions.last
version.item_type    # "Listing"
version.item_id      # 42
version.event        # "update"
version.whodunnit    # "7" (user ID)
version.object       # { "address" => "350 Fifth Ave", ... } (previous state)
version.object_changes # { "price" => [1200000, 1150000] } (what changed)
version.created_at   # when
```

### Ignoring noisy attributes

Some attributes change frequently but aren't meaningful to audit:

```ruby
class Listing < ApplicationRecord
  has_paper_trail ignore: [ :updated_at ]
end

class Player < ApplicationRecord
  # Not tracked — but if it were:
  has_paper_trail ignore: [ :last_heartbeat_at, :ip_address, :user_agent ]
end
```

## Account scoping on versions

Add `account_id` to the versions table so versions can be scoped
to an account without joining back to the source models. This
prepares for future activity feeds without requiring them now.

```ruby
# migration
add_column :versions, :account_id, :bigint
add_index :versions, :account_id
```

Set it automatically:

```ruby
# app/models/application_record.rb
class ApplicationRecord < ActiveRecord::Base
  self.abstract_class = true

  # Set account_id on paper_trail versions for tenant scoping
  def paper_trail_metadata
    { account_id: Current.account&.id || try(:account_id) || try(:account)&.id }
  end
end
```

## Data retention

Versions accumulate over time. A monthly cleanup job prunes
versions older than 90 days (configurable per account for
enterprise tier):

```ruby
# app/jobs/version_cleanup_job.rb
class VersionCleanupJob < ApplicationJob
  def perform(retention_days: 90)
    PaperTrail::Version
      .where("created_at < ?", retention_days.days.ago)
      .in_batches
      .delete_all
  end
end
```

## Build order

### Phase 1 — paper_trail setup
1. Add `paper_trail` gem + bundle install
2. Run install generator, customize migration for `jsonb` columns
3. Add `account_id` column to versions table
4. Run migrations
5. Configure initializer (`track_associations = false`)
6. Set `whodunnit` in `App::BaseController`
7. Add `paper_trail_metadata` for `account_id` on ApplicationRecord

### Phase 2 — Track core resources (RED/GREEN)
8. RED: Spec that Listing, Ad, Playlist, Lead create versions on changes
9. GREEN: Add `has_paper_trail` with `ignore` to those 4 models

### Phase 3 — Track remaining resources (RED/GREEN)
10. RED: Spec that Agent, Site, Screen, Player create versions
11. GREEN: Add `has_paper_trail` with `ignore` to those 4 models

### Phase 4 — Track auth + join models (RED/GREEN)
12. RED: Spec that User, AccountUser, Invite create versions
13. GREEN: Add `has_paper_trail` to those 3 models
14. RED: Spec that join models (PlaylistAd, ScreenPlaylist, ScreenPlayer, LeadAgent, ListingAgent) create versions
15. GREEN: Add `has_paper_trail` to those 5 models

### Phase 5 — Cleanup
16. `VersionCleanupJob` — prune versions older than 90 days (RED/GREEN)
17. Solid Queue recurring job config
18. Full suite green, lint clean

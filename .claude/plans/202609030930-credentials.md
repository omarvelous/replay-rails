# Plan: Rails Credentials for Secrets Management

## Problem

R2 storage keys and other secrets are managed via Render env vars
and `render.yaml` `sync: false` entries. This spreads secrets
across two places (Render dashboard + code) and requires manual
setup per environment. Rails credentials provides a single encrypted
file per environment committed to the repo, unlocked by one key.

## Goal

Move all secrets into per-environment Rails credentials. The only
env var needed in Render is `RAILS_MASTER_KEY`.

## File structure after migration

```
config/credentials.yml.enc            → shared (development/test)
config/master.key                     → shared key (gitignored)
config/credentials/staging.yml.enc    → staging secrets
config/credentials/staging.key        → staging key (gitignored)
config/credentials/production.yml.enc → production secrets
config/credentials/production.key     → production key (gitignored)
```

Rails auto-loads the right file based on `RAILS_ENV`.

## What goes where

| Secret | Credentials | Env var | Why |
|--------|:-:|:-:|-----|
| R2 access key | Yes | No | Same across deploys, rarely changes |
| R2 secret key | Yes | No | Same |
| R2 endpoint | Yes | No | Same |
| R2 bucket | Yes | No | Per-environment |
| `RAILS_MASTER_KEY` | No | Yes | Unlocks the credentials file |
| `DATABASE_URL` | No | Yes | Render injects from managed DB |
| `RAILS_ENV` | No | Yes | Determines which credentials to load |
| `RAILS_LOG_TO_STDOUT` | No | Yes | Infrastructure, not a secret |
| `RAILS_SERVE_STATIC_FILES` | No | Yes | Infrastructure, not a secret |

## Build order

### Phase 1 — Create per-environment credentials

1. Create staging credentials:
   ```bash
   EDITOR="code --wait" bin/rails credentials:edit --environment staging
   ```
   Add:
   ```yaml
   r2:
     access_key_id: <staging R2 key>
     secret_access_key: <staging R2 secret>
     endpoint: https://<account_id>.r2.cloudflarestorage.com
     bucket: replay-staging
   ```

2. Create production credentials:
   ```bash
   EDITOR="code --wait" bin/rails credentials:edit --environment production
   ```
   Add:
   ```yaml
   r2:
     access_key_id: <production R2 key>
     secret_access_key: <production R2 secret>
     endpoint: https://<account_id>.r2.cloudflarestorage.com
     bucket: replay-production
   ```

3. Commit the encrypted files (`.yml.enc`) — keys (`.key`) are gitignored

### Phase 2 — Update code to read from credentials

4. Update `config/storage.yml`:
   ```yaml
   cloudflare:
     service: S3
     endpoint: <%= Rails.application.credentials.dig(:r2, :endpoint) %>
     access_key_id: <%= Rails.application.credentials.dig(:r2, :access_key_id) %>
     secret_access_key: <%= Rails.application.credentials.dig(:r2, :secret_access_key) %>
     bucket: <%= Rails.application.credentials.dig(:r2, :bucket) || "replay-#{Rails.env}" %>
     region: auto
     request_checksum_calculation: when_required
     response_checksum_validation: when_required
   ```

5. Update `config/environments/production.rb`:
   ```ruby
   config.active_storage.service =
     Rails.application.credentials.dig(:r2, :endpoint).present? ? :cloudflare : :local
   ```

6. Run tests — verify development still uses local storage

### Phase 3 — Clean up render.yaml

7. Remove R2 env vars from shared groups:
   - Remove `R2_ACCESS_KEY_ID` (`sync: false`)
   - Remove `R2_SECRET_ACCESS_KEY` (`sync: false`)
   - Remove `R2_ENDPOINT` (`sync: false`)

8. Remove `R2_BUCKET` from service env vars

9. Shared groups now only contain:
   ```yaml
   envVarGroups:
     - name: replay-shared
       envVars:
         - key: RAILS_LOG_TO_STDOUT
           value: "true"
         - key: RAILS_SERVE_STATIC_FILES
           value: "true"
         - key: RAILS_MASTER_KEY
           sync: false
   ```

### Phase 4 — Update Render

10. Set `RAILS_MASTER_KEY` per environment in Render dashboard:
    - **Production**: value from `config/credentials/production.key`
    - **Staging**: value from `config/credentials/staging.key`
    - These are different keys (each environment has its own)

11. Remove R2 env vars from Render dashboard (if set manually)

12. Deploy both environments — verify images still load

### Phase 5 — Documentation

13. Update `infrastructure/README.md` — document credentials workflow
14. Update `docs/contributing.md` — how to edit credentials per environment
15. Add to `CLAUDE.md` — credentials convention

## Considerations

- **Shared credentials** (`config/credentials.yml.enc`) still exist
  for development/test. Don't put R2 keys there — dev uses local
  storage.
- **Key management** — staging and production keys must be shared
  securely with anyone who needs to edit credentials. Store them
  in a password manager, not Slack/email.
- **PR previews** — Render preview apps inherit `RAILS_MASTER_KEY`
  from the parent environment's group. They'll use the staging
  credentials, which is correct.
- **CI** — the test suite doesn't need R2 credentials (uses local
  storage). No CI changes needed.
- **Rollback** — if credentials are misconfigured, ActiveStorage
  falls back to `:local` (no crash, just missing images). Safe
  to deploy and verify.
